# Prueba física de aceptación — candidata 1.4.11 (25)

Pendiente de ejecución por el propietario. Estas instrucciones no acreditan una prueba ya realizada.

1. Antes de actualizar, comprobar que la instalación es una Release con la firma histórica; la candidata se contrasta con las APK locales 1.4.9 y 1.4.10. No se verificó la firma instalada en cada tablet. Conservar respaldo de trabajo pendiente. Copiar el APK a la tablet, abrirlo y elegir Actualizar. Si Android informa incompatibilidad de firma o no permite actualizar, detenerse: no desinstalar ni borrar datos. Una instalación Debug con otro certificado no es compatible.
2. Sin Internet, crear datos ficticios Muro, Túnel y Badén, cada uno con observación y fotografía. Guardar borrador y esperar la confirmación local. Volver a Inicio. Abrir cada uno por CONTINUAR y por MIS REGISTROS → Ver detalle → EDITAR. Verificar título/subtipo, UUID, observación y foto. No utilizar fichas de ingenieros para estas comprobaciones.
3. Mantener los tres borradores, alternar entre ellos, editar una observación y girar la tablet sin guardarla todavía. Confirmar que no cambia el subtipo ni se pierde el texto. Guardar, salir y cerrar/reabrir la app; comprobar los tres registros, sin duplicados ni fotos perdidas. Esta reapertura física sigue pendiente, aunque la recreación y Room se probaron localmente.
4. Si un borrador histórico presenta conflicto, debe indicar Borrador conservado. No intentar convertirlo ni repararlo sin respaldo y revisión inequívoca. Para diagnóstico: Inicio → DIAGNÓSTICO DE ESTABILIDAD → Exportar diagnóstico. El informe incluye fases/códigos acotados y huellas/conteos de PR, sin textos de fichas, fotografías, coordenadas o credenciales.
5. Para PE-28H / CD, comparar 0010+010 → 0011+180. Sin equivalencias contractuales acreditadas debe quedar Pendiente; no dar por supuesto 1170 m. Si otra tablet calcula un número, comparar versión y diagnóstico local y acreditar los PR antes de certificarlo. Los PR FIELD_CAPTURED no prueban por sí solos la calibración contractual.
6. Confirmar persistencia local y cola offline. Una subida real de prueba a Drive requiere autorización separada. Un archivo generado o un contador parcial no acredita ACK. No modificar Apps Script ni enviar datos productivos como parte de esta lista.

Registrar: modelo/Android, versión instalada anterior, resultado por subtipo, UUID únicamente en evidencia privada autorizada, fotos/observaciones conservadas, giro/reinicio, longitud y resultado de actualización. No introducir PIN, token, URL privada ni fotos reales en el informe compartido.

**Criterio:** GO para validación física controlada; la distribución de campo sigue pendiente de esa aceptación y de validar las referencias contractuales utilizadas.
